The card

The card floats above other windows and reads the Netskope client's own logs. It asks for no permissions and captures nothing from the screen.

LOG, SWG, NPA

Three views of traffic: private app requests, SWG flows, and NPA detail.

GSLB

The antenna button lists every data plane the client measured, by round trip, with the connected one marked. Click one for its history graph.

Manufactured failover

Right-click a data plane in the GSLB view to add latency or fail it, and watch the client move. Released automatically.

Always on Top

On: the card floats over everything, on every desktop. Off: an ordinary window with a Dock icon. Toggle it from the menu bar menu.

Setup

On first launch the window opens on Setup. Two things are needed once.

  1. Install the PathSkope Helper. The steps that need root run through one small script, installed once with your administrator password.
  2. Save a tenant. Either add the tenant the client is on now, or register one with its details: tenant name and region, org key, email, auth token, and the encryption token if the tenant uses one. PathSkope checks them against the tenant before saving.

The Netskope client does not have to be installed for setup to complete. Without it the card has nothing to show, but a switch still writes the tenant files for whenever the client is installed and started.

Tenants and switching

Register a tenant once. From then on switching is one click from the card's tenant menu, or the Switch button in Settings, Tenants. The tenant the client is on now is shown in green.

While a switch runs, a progress window shows the three stages and a Details log. Stop switch ends it and leaves the client running. Stop waiting only stops watching for the tunnels. After a failed switch, Enrol again from fresh runs it again with the cached files ignored.

The window

Everything that is not the card is one window: Settings from the menu bar menu, or ⌘,.

Client Configuration

Opened from the bottom of the card, or Tools in the menu. Read from the client's own files; anything named like a key, token or password is left out.

Overview

Tenant and enrolled user, client version and configuration, steering configuration and traffic mode, device classification, client status, and every client setting with a filter.

NPA Policy

Every private app rule the client holds: app, policy, hosts, ports, publishers. Searchable.

DC Pinning

Every data plane worldwide from the Netskope trust portal. Pin the client to one, or to a country, and unpin.

Logs

PathSkope's own log: switches, updates and the app. Tick Everything for the tunnel chatter.

Updates

Nothing is installed without pressing Install. Tenants and settings are kept across updates. Beta builds are offered only if you turn that on. Previous versions are listed so you can go back. The helper has its own line in the same section: when a build ships a newer helper, install it there.

What is stored, and how

Security, in Settings, has one switch: use Touch ID instead of a password for privileged actions. Switching a tenant, restarting the client, pinning and shaping each ask before they run, and one approval covers a whole switch.

The helper

Writing the client's tenant files, restarting it, pinning a data plane and shaping traffic all need root. They run through one small script, the PathSkope Helper, installed once with your administrator password. It accepts a fixed set of commands, checks every argument, and cannot be used as a general root shell. Settings, Updates shows the installed version; when a build ships a newer one, install it there, and roll back the same way if it misbehaves. Removing it stops switching, pinning and shaping; everything else carries on.

When something goes wrong

A switch sits on Restarting client

Press Stop switch. The client is left running. Then Enrol again from fresh, or switch again.

The tenant refused the enrolment

The service sometimes times out and reports it as a refusal. Wait a moment and switch again. If it persists, check the tenant's org key and auth token in Settings, Tenants.

"Stored details could not be read"

The saved details are intact but this build could not open them. Install the recommended build from Settings, Updates.

NPA shows Not required

That tenant does not steer Private Access. Nothing to fix. The same applies to Endpoint DLP and Borderless SD-WAN.

The card is behind other windows

Turn Always on Top on from the menu bar menu. With it off, the Dock icon, Mission Control and ⌘-Tab bring it back.

Details for a switch

Every switch is in Client Configuration, Logs, with the client's own failure lines copied in beside PathSkope's.
